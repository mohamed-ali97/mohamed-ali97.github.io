الـ Mapping بالـ Graphical Data Mapping editor

Mapping messages with the Graphical Data Mapping editor

بدل ما تكتب كود ESQL لتحويل الرسالة، تقدر ترسم التحويل بالـ Graphical Data Mapping editor. هتتعلم الـ message maps، الـ Mapping node، إزاي تنشئ map، وأنواع الـ transforms.

صفحات الكتاب: PDF صفحات 490-534

أهداف الـ Unit

  • استخدام الـ Graphical Data Mapping editor لعمل map للـ logical messages
  • تشغيل message maps داخل message flows

القسم 9.1: نظرة عامة على الـ message maps

إيه هي الـ message map؟

  • بتحوّل logical message من غير كود: صورة بصرية للتحويل بتسهّل التنفيذ والصيانة
  • بتركز على التحويل الهيكلي للرسالة (structural transformation) مش على تسلسل الخطوات

الـ message map هي تنفيذ ACE للـ graphical data map. مبنية على معايير XML schema وXPath 2.0 مع دعم إضافي لـ JSON schema draft 4 وSwagger 2.0. تقدر تستخدمها لتحويل وتوجيه وإثراء الرسالة أو لتنفيذ REST API.

تقدر تستخدم الـ map لـ:

  • تحويل أي جزء من الـ logical message assembly (headers وproperties وbody)
  • إثراء (enrich) الرسالة ببيانات من database خارجية
  • تعديل بيانات في database خارجية
  • توجيه الرسالة حسب محتواها

خطوات الاستخدام

  1. صمم وعرّف الـ map للتحويلات المطلوبة
  2. نادي الـ map بـ Mapping node

خيارات الـ mapping مش نفسها لكل أنواع الـ nodes. تعيينات الـ target ممكن تتحسب أو تتجمع من مصادر إدخال متعددة (رسايل أو جداول database) كـ many-to-one أو many-to-many، وممكن تكون شرطية.

تلات أنواع map models (لا يمكن تغييرها بعد الاختيار)

Complete message map
بتعمل map للـ properties وكل الـ headers والـ message body وأجزاء من LocalEnvironment (DestinationList)
Simplified message
بينسخ كل الـ headers الموجودة. أنت بتعمل map للـ properties والـ body والـ LocalEnvironment بس
Submaps
بتعمل map لأجزاء من الـ message body فقط. مينفعش تستخدم في nodes مباشرة
تنبيه
التزم (commit) بتغييرات الـ message models وجداول الـ database قبل ما تستخدمها في maps.

تنفيذ الـ message map

  • بتتستخدم في nodes مختلفة: Map target = Message (Mapping node)، أو Map target = Database
  • قابلة لإعادة الاستخدام وبتقابل الـ nodes: الـ nodes بتشير لـ message map للـ properties والـ headers والـ body
  • بتتخزن في ملفات *.map وبتتعرض كـ XML schemas. لازم يشير لها message flow application
  • الـ submaps بتعمل map لـ complex type في الـ message body

الـ submap شكل قابل لإعادة الاستخدام من الـ graphical data map: بتستخدم مجموعة دوال mapping في maps متعددة لتحويل مجموعة عناصر مشتركة، فتعيد استخدام تحويلات شائعة.

نشر الـ message map

  • افتراضيًا ملفات الـ map بتتنشر في BAR files كموارد منفصلة. لو غيرت map لازم تعيد نشر الحل
  • ACE بيجهز الـ maps لوقت التشغيل أثناء النشر، مش لما أول رسالة تعدي على الـ Mapping node. فمفيش بطء عند أول رسالة بعد نشر أو restart
  • الـ map واعتماديتها (زي message models المشار لها) بتتحل وتتفحص وقت النشر لضمان إنها تشتغل من أول رسالة
  • صياغة الـ map بتتفحص وقت النشر
  • عند restart لـ ACE، صياغة الـ map واعتماديتها بتتفحص قبل ما الـ flow يرجع

ملفات الـ map بتتنشر عادةً مع application أو integration service أو library. تقدر تنشر map كمورد مستقل لو بتدير الـ flows بالطريقة دي. وقت النشر بيتأكد إن كل الاعتماديات تتحل وقت التشغيل: XML schema وDFDL schema وmessage set files والـ submaps المشار لها. بعدين الـ maps واعتمادياتها بتتولد لشكل تنفيذي وتتفحص. لو صحيحة بتتخزن بالشكلين (المنشور والمتولد) في configuration store. لو لأ، النشر بيقف وبتستلم رسالة BIP عن فشل توليد الـ map.

الـ maps والـ shared libraries

  • لما الـ logical message يتفحص (validate) مقابل XML schema files منشورة في shared libraries، لازم تحدد اسم الـ shared library اللي فيها الـ model المترجم: خاصية Properties.MessageSet فيها اسم الـ shared library اللي فيها الـ schemas المستخدمة في الـ map
  • خزّن ملفات الـ map في shared library لما: تحتاج نفس الملفات في حلول متعددة، أو نشرت map وعايز تحدثها من غير إعادة نشر الـ application أو integration service
تنبيه
التغييرات في الـ data model ممكن تأثر على الـ map.

الـ message map ممكن تكون في نفس الحاوية مع الـ Mapping node (زي application) أو في shared library مرجعية.

اختيار نوع الـ graphical data map

Message map
graphical data mapping، ملف .map
Submap
إعادة استخدام تحويلات مشتركة، ملف .map
Local map
مفيش ملف: بيتدمج جوه Message map لتقليل التعقيد في قراءة وإدارة الـ Message map
Graphical data map
مشاركة الـ maps بين منتجات برمجية مختلفة، ملف .map
IBM WebSphere Message Broker message map
للحلول المرحّلة من إصدارات أقدم. ملف .msgmap. استخدم Conversion tool للانتقال للتقنية الجديدة
legacy maps
لو عايز تنشر أو تعدل legacy message map بصيغة .msgmap لازم تحوله الأول لـ graphical data map بصيغة .map. الـ graphical data map اسمها message map في ACE.

تتبع مشاكل الـ maps

الـ Mapping node بيبلغ عن تشغيل سكربتات الـ map كأحداث user trace تفصيلية: دخول واكتمال كل transform وتعيين القيم في output الـ map. استخدم user trace لتتبع منطق التحويل في الـ maps.

القسم 9.2: الـ Graphical Data Mapping editor

الـ Mapping node

  • بيستخدم الـ editor لبناء وتعبئة رسايل جديدة: بناء logical message جديدة، أو نسخ logical messages بين parsers، أو تحويلها من صيغة لصيغة
  • موجود في drawer اسمه Transformation في الـ palette
  • خاصية Mapping routine فيها العبارات اللي تتنفذ على الـ database أو الـ logical message tree
  • دبل كليك على الـ node أو كليك يمين > Open Map لفتح الـ mapping routine
  • لو الـ routine مش موجود: New Message Map wizard بيفتح بقيم افتراضية. لو موجود: بيفتح في الـ editor

تقدر تملّي الرسايل الجديدة بمعلومات جديدة أو معلومات معدلة من رسالة الإدخال أو معلومات من database. وتقدر تعدل عناصر الـ message body وبيئتها وـ exception list.

الـ editor

  • بتعمل map للعناصر والـ attributes بين input وoutput objects، وبعدين تطبق transform على الـ mapping يحدد الإجراءات على الـ input object
  • متصمم كمعيار لمنتجات IBM
  • ميزاته الغنية وبساطته بتخليه الاختيار الافتراضي الجيد للتحويل
  • الـ maps متاحة لـ user patterns: إنشاء flows بصريًا، وبيتنادى عند توليد pattern instances، مع HTML pattern help وtask list
  • دعم كامل لتعبيرات XPath 2.0

الـ source messages (يسار) والـ target messages (يمين) بتظهر في design window. بترسم connectors من source لـ target لتحدد الحقول المنسوخة والـ transforms المطبقة. بعد ما تعمل map، بتتفحص وتتترجم تلقائيًا وتبقى جاهزة للإضافة لـ BAR file والنشر.

متطلبات
الـ models المشار لها في الـ map لازم تكون في الـ workspace. لو الـ map بتشير لـ database، لازم ملف database definition (.dbm) في الـ workspace. لازم يكون عندك message models لأي رسالة عايز تدخلها في الـ mapping. مدعوم: DFDL وXML schema files وMRM message sets.

التنقل في الـ editor

Map view
فيه map sources وtargets وtransformations
Outline view
أداة تنقل بتبين بنية الـ map. لما تضغط transform فيه، الـ Map view بيتحدث. افتراضيًا بيظهر مع Properties وممكن تسحبه ليظهر مع Integration nodes
Properties view
خصائص الـ transform المختار

الـ Map view فيه نموذج بيانات الـ source على الشمال وبيانات الـ target على اليمين. لو البيانات فيها groups داخل groups ممكن تحتاج submap لعمل map لـ objects في subgroup. فيه أيقونات level navigation وnavigation trail للتنقل من main map لـ submap والعودة.

Toolbar الـ editor

  • إضافة أو حذف حقول من source أو target
  • ترتيب الحقول (Sort mapping by target أو by source)
  • Auto map input to output
  • Add transform
  • Add / Remove environment mapping
  • Delete selected element
  • عمليات database: Select rows وDelete row وInsert row وUpdate row وCall database routine
  • Show preferences

تقدر تتحكم في مدى التشابه المطلوب بين أسماء وأنواع الحقول في الـ auto map، وتجيب rows من database وقت التشغيل لإدخالها في الـ target.

القسم 9.3: إنشاء message map

  1. في Message Flow editor ضيف Mapping node على الـ canvas
  2. دبل كليك على الـ Mapping node: يبدأ mapping wizard. حدد الخصائص: Container وMap name ونوع الـ map وbroker schema
  3. اختار الـ source (input) والـ target (output). تقدر تختار أكتر من واحد. وسّع قائمة الـ objects واختار، واستخدم Filter map fields للفلترة
  4. الـ editor بيفتح بالـ source والـ target، وبينشأ تلقائيًا Move transform بين Properties folders

وتقدر تنشئ map من Integration Development perspective: File > New > Message Map، وساعتها لازم تختار النوع:

  • Simple message map called by a message flow node: map يتنادى من node
  • Submap called by another map: map يتنادى من map تاني

إنشاء transform بين عنصرين

  1. حط الماوس على الـ object في الـ source: يظهر wiring handle أصفر
  2. اسحبه لـ object في الـ target. بتتعمل connection ويظهر default transform

لتغيير الـ transform اضغط السهم الصغير لتحت في اسمه واختار transform جديد.

طرق إنشاء transforms

Option 1
اسحب من source لـ target
Option 2
اعمل connection أو transform من menu action على الـ source أو target المختار (كليك يمين)
Option 3
لما ما تقدرش تلاقي الـ source والـ target مع بعض، اختار Quick Link، واستخدم quick outline view وfilter فيه لإيجاد العنصر المطلوب

بعد اختيار الـ source والـ target بيتنشأ أنسب transform.

Core mapping transforms (مجموعة جزئية)

Assign
يحط قيمة في عنصر output. مفيش input element. القيم المحطوطة بـ Assign لأعمدة database بتتمرر دايمًا كـ character string
Built-in XPath
كل دوال XPath 2.0 مدعومة بالشكل fn:<function_name>
Concat
يدمج string من كيانين أو أكتر في نتيجة واحدة
Convert
ينسخ input لـ output ويغير النوع: input بسيط واحد → output بسيط واحد بنوع مختلف
Create
ينشئ element فاضي أو nil أو simple type بقيمة افتراضية حسب نوع العنصر
Custom XPath
تكتب أي XPath expressions ودوال ACE المدمجة
Custom Java
تكتب كود Java خاص
Custom ESQL
تكتب كود ESQL خاص
Default / Fixed (Cast)
يحط نوع قيمة معين في output. Cast كمان ممكن ينقل ويحوّل input لنوع معين
Move
ينسخ البيانات من input لـ output
Normalize
ينضف الـ string بإزالة المسافات والـ tabs والـ returns وينقله لـ output
Substring
يستخرج جزء من string وينقله
Task
يوصف مهمة يدوية أو نقطة قلق محتاجة مراجعة قبل استخدام الـ map

دوال الـ string تشمل: الطول والـ padding وقراءة system property وتغيير case والمقارنة والدمج والـ substring والـ translate وغيرها. الـ custom transforms بتخليك تكتب Java أو XPath يتنادى وقت التشغيل.

Database transforms

Database Routine
يستدعي stored procedure أو user-defined function
Delete
يمسح صف أو أكتر مطابق لـ Where clause
Failure
يخلي الـ map تتعامل مع أخطاء database server في database transform بدل ما توقف الـ map ويتبلغ عنها
Insert
يدخل صف في جدول
Return
معالجة إضافية بعد نجاح Insert أو Update أو Delete أو Database Routine call. بيوفر النتايج كـ inputs
Select
يجيب بيانات من صفوف جدول لاستخدامها كـ input في الـ map
Update
يحدّث صف أو أكتر مطابق لـ Where clause بمجموعة قيم واحدة

لكل database transform، الـ editor بيستخدم ملف database definition (.dbm) ليعرف اسم وبنية الـ database. تقدر تشغل wizard لإنشاء .dbm لما تنشئ database transform.

Structural mapping transforms

بتتحكم في طريقة عرض العناصر المتداخلة في الـ editor ومالهاش تأثير على البيانات نفسها:

Append
يضيف occurrences لـ output array بترتيب الـ inputs
Remove
يشيل element
For Each
يكرر على input array (بسيط أو معقد)
Group
ياخد input array واحد وينتج مجموعة arrays متداخلة بتجمّع عناصره
If, Else if, Else
تتحكم في تدفق الـ mapping بشروط. بتشتغل كمجموعة. الشرط بيتطبق على الـ input element، ولو اتحقق الـ transform المتداخل فيه بيتنفذ
Join
يجمع عناصر من اتنين input أو أكتر
Local map
عرض هرمي لـ element transforms. transform بـ input واحد (بسيط أو معقد) وممكن يحتوي nested maps. الـ target عنصر واحد أو array لكن لازم complex type
Submap
يشير لـ map تانية، من نفس الملف أو ملف تاني في library أو application أو integration service أو project

خصائص الـ transform

كل transform بيتظبط في Properties view:

General
القيمة أو التعبير اللي بيحدد قيمة output element
Variables
أسماء المتغيرات للـ input connections المستخدمة في التعبيرات
Condition
تعبير XPath يحدد هل الـ transform يتطبق
Order
إعادة ترتيب input connections لـ transforms زي Append
Documentation
توثيق الـ transform
Cardinality
العناصر في array المراد تحويلها (indexes)
Filter Inputs
تعبير يحدد هل كل عنصر متكرر يتطبق
Sort
إعادة ترتيب input array connections

نوع الـ transform بيحدد التبويبات المتاحة. اضغط Alt+Enter لفتح Properties view لما الـ Map Editor في وضع full screen.

القسم 9.4: Mapping elements

Auto map

  • Auto map wizard بينشئ Move transforms تلقائيًا بين العناصر حسب مدى تشابه الأسماء
  • Map all simple descendants of the selected elements (الافتراضي): يطابق أحفاد الـ input بأحفاد الـ output
  • Map the immediate children: الأبناء المباشرين بس
Case sensitive
هل الحالة (كبير/صغير) تهم في المطابقة
Alphanumeric characters
حروف وأرقام بس، يستبعد الرموز الخاصة
Same names
ينشئ transforms لما الأسماء متطابقة (الافتراضي)
More similar than
تحدد درجة التشابه المطلوبة
Synonyms file
ينشئ mappings لأزواج كلمات معرفة في ملف synonyms: ملف نصي عادي بامتداد .txt أو .csv

Primary وsupplementary inputs

Primary inputs
داخلة مباشرة في التحويل: فيها البيانات لإنتاج الـ output، وممكن تحدد خصائص الـ transform
Supplementary inputs
بتمرر عناصر للـ transform من غير تأثير على الغرض الأساسي. مش بتتستخدم مباشرة في التحويل، ممكن تحدد خصائص الـ transform، ممكن يكون منها عدد غير محدود، وممكن تمرر بيانات زيادة لـ nested map

الـ local map له primary input واحد وعدة supplementary inputs (بسيط أو معقد). لازم تعمل map للعناصر في nested map وإلا ما يحصلش أي إجراء. في مثال الكتاب: For Each بيستخدم Price كـ primary input وCurrency كـ supplementary لحساب Cost. تستخدم الـ supplementary في: عمل Filter Inputs expression حسب قيمة الـ input، أو تمرير عنصر إضافي لكل iteration، أو ضبط Cardinality لتحديد index الـ array.

XPath 2.0 في الـ editor

  • منطق شرطي: عرّف تعبير في تبويب Condition. لو true الـ transform بيتقيم والـ target بيتنتج
  • حسابات رقمية: sum وcount وround وmaximum وminimum مدمجة
  • معالجة strings: تقسيم ودمج ومقارنة
  • Custom XPath transform لتوليفات أعقد
  • الـ editor فيه content assist

User-defined elements

عنصر بتضيفه لـ message map لتعريف مكونات message assembly: JSON messages وGlobal أو Local Environment وعناصر xsd:any في الـ body أو الـ headers (نقاط التمديد: any أو anyAttribute). أنواع: simple type وcomplex type وrepeatable. تقدر تضيف وتعيد استخدام وتعيد تسمية وتحوّل وتحذف أثناء التطوير. أماكن النقاط: متغيرات LocalEnvironment، الـ message body، عناصر xsd:any، الـ Environment tree، والـ transport headers اللي فيها extension points زي MQRFH2. وتستخدمها لتعريف JSON message أو SOAP/XML بـ xsd:any.

  • تعريف simple أو complex user-defined element في input أو output
  • attributes جوه complex user-defined element
  • repeatable simple type جوه complex type
  • إعادة ترتيب ونسخ ولصق
  • JSON-specific array type
  • تقدر تحدد النوع من global type definition موجود (message models أو XML schemas أو DFDL schemas)
  • عناصر JSON بتتعرف nillable افتراضيًا لدعم JSON null

Mapping JSON object messages

  • تقدر تختار JSON message map كـ source أو target
  • الرسالة JSON = عنصر واحد من نوع JSONMsgType فيه أبناء
  • Padding element (اختياري): لتمرير استدعاء دالة JavaScript للـ JSONP services
  • Data element لنمذجة رسالة JSON: Data anyType (بـ Cast، لما عندك schema model بيعرّف الـ JSON) أو Data JSONObject (بـ Add User-Defined، لتحويل بعض عناصر الـ JSON object)

لما تنشئ map تقدر تختار JSON object message أو JSON array message. النماذج الجاهزة في فئة IBM supplied message models. لما تختار JSON message model كـ output، الـ output domain بيتضبط تلقائيًا على JSON. لازم تعرّف واحد بس من عنصري Data. ممكن تستخدم Cast لتعريف الـ JSON message أو جزء منه بـ schema model.

نصايح اختيار الـ transform لـ JSON

  • Assign: قيمة ثابتة من غير input
  • Create: قيمة فاضية أو JSON NULL (nil) من غير input
  • Move: نسخ قيمة input
  • If أو XPath أو custom: شرط لتحديد قيمة output
  • Append أو Group أو For each أو Join أو XPath أو custom: لقيمة JSON array
  • Select أو Database Routine: قيمة من database
  • xs:type: cast لقيمة input بسيطة لنوع معين
  • fn:type: قيمة بدوال XPath 2.0

Properties mapping

الرسالة فيها: الـ Properties tree (محددة سلفًا من الـ integration node: الصيغة الفيزيائية وجودة الخدمة للنقل ومعلومات مسار الرد وtopic الـ publish/subscribe)، وـ headers خاصة بالبروتوكول، وLocalEnvironment (للتوجيه الديناميكي مثلًا). الـ Mapping node بينسخ الـ properties والـ headers من input لـ output من غير تغيير افتراضيًا.

MRM
لازم تعمل map للـ Properties folder لما تحتاج output مبني على MRM parse tree. لو ما عملتش، الرسالة ما بتتبعتش بالكامل. مش مطلوب في domains تانية.

Mapping الـ Environment وLocalEnvironment

  • تقدر تضيف Environment tree لـ message map وتنمذج المحتوى بـ User-Defined elements أو casts، وتحدّث أو تنشئ أو تشيل عناصر بـ transformations بين عناصر الـ Environment وأي عناصر في message assembly
  • كل محتوى Environment بيتنقل دايمًا من input لـ output

الـ LocalEnvironment جزء من الـ logical message tree بتخزن فيه معلومات أثناء معالجة الرسالة (متغيرات تقراها وتعدلها nodes لاحقة، وتحديد الوجهات الداخلية والخارجية). لما تضيفه لـ message map لازم تعمل transforms لكل عناصره عشان قيم الـ input ما تضيعش. تنسخ الحقل كما هو أو معدل. كتير من nodes ACE بتعتمد على الـ local environment. لو ما اتضافش للـ map، الـ Mapping node بينسخه من input لـ output كما هو.

Message map هو تطبيق ACE لـ graphical data map، مبني على معايير XML Schema وXPath 2.0 (مع دعم JSON schema draft 4 وSwagger 2.0). بتحوّل وتوجّه وتثري الرسالة أو تنفذ REST API من غير كتابة كود، بصورة مرئية بتسهّل التنفيذ والصيانة.
نص الكتاب الأصلي
A message map is the IBM App Connect Enterprise implementation of a graphical data map. It is based on XML schema and XPath 2.0 standards, with additional support for JSON schema draft 4 and Swagger 2.0. You can use a message map to graphically transform, route, and enrich a message, or implement a REST API. Maps provide a simple way to transform logical messages. You transform an input message into an output message with a map, by following these steps: 1. Design and define the map to do the required transformations. 2. Call the map by using a Mapping node that calls the map. The mapping options available are not the same for all node types. Target assignments can be calculated or combined from various input sources, which can be in the form of messages or database tables, as with many-to-one or many-to-many mapping. Target assignments can also be conditional based on a combination of factors that can be applied to any type of mapping. You must select one of three different map models, which cannot be changed later: • Complete message maps properties, all headers, message body, and parts of the LocalEnvironment (DestinationList). • Simplified message copies all existing headers. You must map only the properties, body, and LocalEnvironment. • Submaps map (parts of) the message body only; it cannot be used in nodes directly. It is important to commit changes to message models and database tables before using the messages or tables in maps. In IBM App Connect Enterprise, the Graphical Data Mapping editor is used to create maps.

A message map is the IBM App Connect Enterprise implementation of a graphical data map. • Maps are used to map a message in a Mapping node. You can also use a message map to enrich, or conditionally set the output message with data from a database table. • You can use a message map to graphically transform a message assembly, message body, and properties, according to the transforms and XPath functions defined in the message map. • A map is based on XML schema and XPath 2.0 standards. It is stored in a .map file. • A submap is a reusable form of graphical data map. Submaps can use a set of mapping functions in multiple graphical data maps to transform a common set of elements in the input object to the output object. You can use a submap to reuse common data transformations.

You select JSON (JSON object message model supplied by IBM) to create a JSON object message. The predefined JSON message contains a single element value of type JSONMsgType. This element contains the following child elements: • A Padding element: This element is optional. You define its value to pass a user-defined JavaScript function call used by JSONP services. • Two Data elements: You define only one of the Data elements to model your JSON message. ▪ You define the element Data, of type anyType, by using the Cast function. You define this element when you have a schema model that defines your JSON message. If you create your map programmatically, you can cast Data to some type in an external schema file, which can define either a JSON object or a JSON array message. ▪ You define the element Data, of type JSONObject, by using the Add User-Defined function. You define this element when you want to transform some elements of your JSON object message. You can also use the Cast function to define the JSON message, or a part of it, with a schema model.

The message assembly can also contain: • The Properties tree, which the integration node predefines • Protocol-specific transport headers, which might have to be manipulated as part of the mapping transformation • Local environment, which is used for functions such as dynamic setting of a message destination (routing) By default, the Mapping node copies the properties and headers from input to output, unchanged. The slide shows the simplified message assembly within the Properties folder in the traditional mapping editor, with some comments that describe the content of the virtual header. The Properties folder must be mapped whenever an output message based on the MRM parse tree is required. If the mapping is not done, the message is not fully propagated. Mapping is not required for other parser domains.

Figure 9-35 Mapping the Environment tree

Environment/LocalEnvironment mapping: تقدر تضيف شجرة Environment للـ map وتمثلها بـ user-defined elements. الـ LocalEnvironment بتخزن متغيرات للـ nodes اللي بعد، وتحدد وجهات (destinations) للتوجيه الديناميكي.
نص الكتاب الأصلي
• The LocalEnvironment tree is a part of the logical message tree in which you can store information while the message flow processes the message. You use the LocalEnvironment tree to store variables that can be referred to and updated by message processing nodes that occur later in the message flow. You can also use the LocalEnvironment tree to define destinations (that are internal or external to the message flow) to which a message is sent. • When you add the LocalEnvironment tree to a message map, you must provide transforms for all of its elements so that the input values of each element are not lost. You can copy the input field unchanged or modified by a transform. Many IBM App Connect Enterprise nodes depend on information in the local environment tree that is copied during the message flow. • The Mapping node copies the LocalEnvironment trees from input to output, unchanged, when they are not included in the message map.
