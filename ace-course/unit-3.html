Creating message flow applications

  • تعبّي (package) وتنشر (deploy) التطبيق والموارد

القسم 3.1: إنشاء message flow

الـ Quick Starts

Figure 3-5

الـ Toolkit بيسرّع التطوير بطرق بداية جاهزة. تقدر تبني message flow application عن طريق:

  • إنشاء application من الصفر
  • إنشاء integration service (application متخصصة بواجهة وهيكل واضحين)
  • إنشاء REST API بعد ما تستورد Swagger document بيوصف الـ resources والـ operations
  • إنشاء library
  • البدء من ملف WSDL أو XSD
  • اكتشاف service (discovering a service)
  • استخدام pattern جاهز (من Unit 2)

الـ Tutorials Gallery

Figure 3-6

الـ Toolkit فيه tutorials بسيطة، بتفتحها من صفحة Welcome أو Help > Tutorials Gallery. الفرق بينها وبين الـ pattern: الـ pattern قالب قابل للتخصيص، أما الـ tutorial فهو مثال كامل شغال لحل ACE كامل. فيه tutorials لميزات معينة زي معالجة الملفات والتحويل والـ modeling.

الخطوة 1: إنشاء application

Figure 3-7
  1. اضغط New Application في Application Development view
  2. اكتب اسم الـ application واضغط Finish

لو مالقيتش pattern يناسبك، اعمل application وبعدين عرّف الـ flow والموارد. الـ application حاوية لكل الموارد المطلوبة: flows وmessage definitions وJAR files. ترتيب إنشاء الموارد مرن: ممكن تبدأ بـ application وتضيف عليها، أو تبدأ بمكتبات وبعدين تعمل application تشاور عليها.

الخطوة 2: إنشاء message flow

Figure 3-8
  1. اضغط New > Message Flow تحت الـ application
  2. اكتب اسم الـ flow (وممكن broker schema جديد يعكس الموارد اللي فيه)
  3. اضغط Finish: الـ flow بيتضاف للـ application وبيتفتح في Message Flow editor

الخطوة 3: إضافة nodes

Figure 3-9
  • الـ Palette بتقسّم الـ nodes لأدراج (drawers) حسب النوع والوظيفة. مثلًا درج IBM MQ فيه MQInput وMQOutput وMQGet
  • اسحب الـ node من الـ Palette للـ canvas. أو اضغط على الـ node في الـ Palette وبعدين اضغط على المكان اللي عايزه في الـ canvas
  • لما تضيف node، الـ Properties view بيتحدّث ويعرض خصائصه، مقسّمة على tabs
  • الخصائص الإلزامية عليها نجمة (*). افحص كل الـ tabs وتأكد إنك دخلت قيمة لكل خاصية إلزامية

الخطوة 4: توصيل الـ nodes بأسلاك (Wiring)

Figure 3-10
  • اضغط على الـ source terminal وبعدين الـ target terminal
  • أو كليك يمين على الـ node > Create connection واختار الـ nodes والـ terminals بالاسم
  • حرّك الماوس فوق terminal لتعرف اسمه، وفوق السلك لتعرف المصدر والهدف
  • الخطوط الاتجاهية بتبين اتجاه حركة الرسالة
خطر
لو وصلت terminal غلط، هيحصل معالجة غلط وممكن تضيع رسايل. ولو node بعت رسالة عبر terminal غير موصول، الرسالة بتضيع من غير تحذير من الـ integration node. بعد التوصيل راجع كل سلك، وتقدر تستخدم Outline view لتشوف كل الـ nodes وتوصيلاتها.

الخطوة 5: الحفظ

Figure 3-11
  • File > Save، أو أيقونة Save، أو Ctrl+S، أو قفل الـ editor واضغط Yes
  • النجمة قبل اسم الملف معناها فيه تغيير مش محفوظ
  • الكائنات ملفات على الـ file system، فأي تعديل لازم يتحفظ
  • وقت الحفظ الـ editor بيعمل validation أساسي: بيتأكد إن كل الخصائص الإلزامية ليها قيمة، وإن المراجع الخارجية (maps أو message models) موجودة. الأخطاء والتحذيرات بتظهر في Problems view

القسم 3.2: نشر BAR file (Deploy)

لما الـ flow يخلص، لازم هو وكل مكوناته يتنقلوا (deployed) لـ integration server عشان يشتغلوا. لو بتختبر بالـ Flow exerciser، التطبيق بيتنشر تلقائيًا. غير كده لو عايز تحكم أكتر لازم تعمل BAR file وتنشره يدويًا.

خطوات النشر الستة

Figure 3-13
  1. اعمل BAR file فيه الموارد اللي هتتنشر
  2. تأكد إن الـ integration server شغال
  3. جهّز الـ queues والـ DSNs (أسماء مصادر البيانات) اللي محتاجها الـ nodes
  4. انشر أي shared libraries بيستخدمها التطبيق
  5. انشر الـ BAR على الـ server بأي طريقة: الـ Toolkit، أو الـ web UI، أو الأمر mqsideploy، أو الـ Integration API
  6. راقب الـ Deployment log لحالة النشر

أثناء النشر، الـ BAR بيتفك والمكونات بتتحط في مكتبات الـ integration server.

عمل BAR file

Figure 3-14
  • من الـ Toolkit: File > New > BAR file
  • أو بالأمر mqsicreatebar أو mqsipackagebar على Windows وLinux
  • لو بتستخدم mqsipackagebar لازم تستخدم mqsicreatebar الأول عشان يعمل compile لأي message sets وكود Java
  • mqsipackagebar مفيد لعمل BAR على أجهزة مفيهاش Toolkit، وبيتحط في scripts للأتمتة
  • تضيف الـ flow كملف .msgflow أو كـ compiled message flow (.cmf) باختيار Compile and in-line resources
  • مينفعش تضيف نفس الـ flow بصيغتين (.cmf و.msgflow) في نفس الـ BAR
تحذير
لو الـ BAR فيه خليط من موارد compiled وموارد مش compiled، ممكن تحصل نتايج غير متوقعة. وللنشر بصيغة compiled لازم كل الـ subflows تكون في ملفات .msgflow، وكل الـ flow والـ subflow وكود ESQL بيتحطوا (in-lined) في ملف .cmf الأب. ده بيدّي سلوك واضح وقت التشغيل لكن أقل مرونة من النشر بالمصدر.

محتويات الـ BAR

Figure 3-15
  • ملف .msgflow لكل message flow
  • message model schemas
  • ملفات XML وstylesheets (.xsl) لـ XSLTransform node
  • ملفات ESQL لـ Compute node أو ملفات Java لـ JavaCompute node
  • ملف broker.xml، وهو الـ deployment descriptor بصيغة XML، في فولدر META-INF جوه الـ zip، وتقدر تعدّله بمحرر نصوص أو shell script

عمل BAR من الـ Toolkit

Figure 3-16 و 3-17
  1. File > New > BAR File
  2. اكتب اسم الـ BAR
  3. أضف المكونات بالـ editor أو اسحبها من Application Development view

تعديل BAR وخصائصه

  • في Manage تقدر تظبط متغيرات تدّي الـ BAR خصائص تشغيل بديلة، فمحتوى الـ BAR (flows وmodels) ميتغيرش لكن السمات تختلف من package لتانية

Validation قبل الـ deployment

Figure 3-21

Enter a message flow name. - Optionally, you can specify a new broker schema name that reflects the resources that the schema contains. - When you click Finish, the message flow is added to the application in the Application Development view and the message flow opens in the Message Flow editor. • The next step is to add the nodes to the message flow.

Figure 3-8 Adding nodes to the message flow

إضافة nodes: (1) دوّر على الـ node في drawers الـ Palette (مثلاً drawer الـ IBM MQ فيه MQInput وMQOutput وMQGet)، (2) اسحبه على الـ canvas (أو دوس عليه واختار مكان)، (3) ظبّط خصائصه في الـ Properties view اللي بتتغير حسب الـ node المختار.
نص الكتاب الأصلي
• The Message Flow editor Palette categorizes the App Connect Enterprise processing nodes in drawers by type and function. For example, the Palette contains an IBM MQ drawer that contains the nodes that act specifically on IBM MQ messages such as MQInput, MQOutput, and MQGet. • You add nodes to a message flow by dragging them from the Palette to the canvas of the Message Flow editor. You can also click a node in the Palette, position the mouse cursor to the location you want in the canvas, and then click to place the node. • As each node is added to the Message Flow editor canvas, the Properties view updates to show the properties that can be defined for the node. Most nodes have multiple properties that are categorized on tabs in the Properties view. • Some properties are mandatory and require a value. Mandatory properties are designated with an asterisk (*). You should always check all the property tabs for a node to ensure that you supplied a value for the mandatory properties.

التوصيل (wiring): دوس على terminal المصدر وبعدين على الـ node الهدف، أو كليك يمين Create connection. الـ wire هو مسار الرسالة. احترس: لو وصلت terminal غلط ممكن تضيع رسايل أو المعالجة تبقى غلط (مثلاً لو node بيبعت رسالة من terminal مش موصول بحاجة، الرسالة بتتفقد).
نص الكتاب الأصلي
• After you place the nodes on the Message Flow editor canvas, the next step is to wire the terminals to other nodes to create a flow. A wire creates a path through which a message can flow. • To wire two nodes together, click the source terminal and then click the target terminal. You can also right-click the source node and then click Create connection to select the nodes and terminals by name. • Use caution when wiring nodes. If you wire the wrong terminal from a node, unexpected results occur, including incorrect processing and possible loss of messages. If a node propagates a message through a terminal that is unwired, the message is lost without warning from the integration node. • After wiring the nodes, hover the cursor over the new wire to be sure that the correct terminals were selected. You can also use the Outline view at the bottom of the Application Development perspective to see all the nodes and their connections.

Figure 3-13 Creating a BAR file

• As is the case with many operations in IBM App Connect Enterprise development, creating and managing BAR files can be achieved in several ways. For example, you can create BAR files by using the App Connect Enterprise Toolkit or by using the mqsicreatebar or mqsipackagebar commands. • The commands can be included in scripts to automate some tasks. For example, you can use the mqsipackagebar command to create deployable BAR files on PCs that do not have the IBM App Connect Enterprise Toolkit installed. This method does not allow the same flexibility as the source deployment, but it does provide an unambiguous runtime behavior. Note: If the BAR file contains a mixture of resources that are compiled and resources that are not compiled, you might see unexpected results.
